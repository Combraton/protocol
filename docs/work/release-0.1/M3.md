## Outcome

An `execution/1` profile that any executor can implement — PIO or a third-party minimal executor — and any caller can rely on, plus the Core effect contract it needs. Conformance must distinguish honest from optimistic executors using a deterministic **scripted executor**. Real harness adapters remain PIO work: their evidence belongs to PIO's own gate, and no M3 fixture depends on a real harness.

## Settled in the draft (recommendations the owner can overturn at review)

1. **Watching reuses Core subscriptions** with `kinds: ["execution"]`; there is no separate watch operation.
2. **Controller leases reuse Core authority epochs**, with scope `execution.controller:<host id>`.
3. **Enforcement levels** are the same three as CORE §17: `enforced`, `mediated`, `cooperative`.
4. **Minimal executor = base profile:** submit, inspect, cancel with a receipt, reconcile, receipts and timeouts. Steering, actions, controller leases, workspaces, usage, context, output, continuation and discovery are features.
5. **Output is an execution-local spool** read by byte offsets. Export as Evidence descriptors comes in M4.

## Test controls, idle expiry and the concurrency regression

- **Clock file** (decision 007). `clock.file` in launch configuration and a runner `set_clock` step. The reference reads its clock from the file on each use. Timeouts (EXE-19), obligation deadlines (EFF-4), liability (EXE-16) and idle expiry (OBS-9) become fast deterministic fixtures.
- **Idle expiry.** On the Unix socket, a subscriber under a grant expiring at T stays idle while the runner moves the clock past T; `ended` must arrive within 2 s with no later item. On stdio, the end comes at the next request.
- **Deterministic regression for the M2 race.**
  - The reference declares barrier `subscription.recheck.after_authorization`.
  - The fixture enables it and waits until the idle subscriber reaches it. It pipelines a revoke and a put on another connection, then releases the barrier.
  - The correct reference holds the processing lock through the re-check, so the revoke waits and the subscriber gets `ended` without the put. Mutant `recheck-outside-lock` delivers the put every run.
- **Pipelined sends and paused reading.**
  - `send` and `expect_response` let a fixture wait for responses in any order, which the pipelined-request fixtures need.
  - `pause_reading` and `resume_reading` model a slow consumer for TRN-4.

## Acceptance

The owner directed on 2026-09-13 and 2026-09-14 that these stay explicit acceptance criteria. None may be dropped silently. If one cannot be met, it is escalated with evidence and recorded as deferred.

1. **Effects and reconciliation (EFF-1 to EFF-4).**
   - Core defines effect descriptors and retry classes.
   - An effect's status can be `unknown` with an open obligation; a closed wait never proves non-occurrence.
   - `execution.reconcile` returns scoped observations and never resubmits.
   - Each row has positive and negative fixtures with killing mutants, for example "reruns on lost acknowledgment" and "reports cancelled on request".
2. **Telemetry lost ranges (OBS-7).** Output travels in a telemetry channel separate from semantic events, with explicit lost-range records. A mutant that drops telemetry silently is killed.
3. **Backpressure (TRN-4).**
   - A slow subscriber is terminated with a typed error and resumes from its cursor.
   - Semantic events are never lost silently, and telemetry coalescing is declared.
   - Fixtures cover a slow consumer on both bindings.
4. **Fault injection.**
   - Deterministic injected faults: delivery ambiguity, a crash between journal and dispatch, lost acknowledgments, late old-attempt results.
   - The `unavailable` and `internal_error` "nothing bound" and "outcome unknown" semantics carried over from M2.
   - SCN-2, SCN-3 and SCN-10 pass on the reference executor over both bindings.
5. **Scripted test executor.**
   - Conformance uses a deterministic reference executor that drives a scripted fake harness selected by launch configuration. The script is test environment, not protocol.
   - A real harness adapter is PIO work: its evidence belongs to PIO's own gate, and no M3 fixture depends on a real harness.
6. **Execution rows.** Every EXE row in scope has positive and negative fixtures with killing mutants.
7. **Test clock.**
   - Launch configuration gains a controllable clock, so timeouts and idle grant expiry during a session become observable.
   - This closes the M2 close-out follow-up on idle expiry.
8. **Independent evidence.** A spec-only helper extends the independent implementation to `execution/1`. It passes, or its divergences are resolved as in M2.
9. **CI.** CI is green, with result manifests, transcripts and mutant summaries uploaded for every job, and outcomes kept distinct (`pass`, `fail`, `timeout`, `harness_error`, `unsupported`, `skipped`).
10. **Idle-expiry coverage (OBS-9).** A portable fixture moves the clock file past a grant's `expires_at` while a Unix-socket subscriber is idle. The subscriber gets `ended` within 2 s and no later item. On stdio the end is reported at the next request. Mutants: ignores the clock file; re-checks only after requests.
11. **Deterministic concurrency regression (REL-13).** A barrier fixture reproduces the M2 idle re-check race deterministically, and mutant `recheck-outside-lock` fails it every run. It is implementation-specific and reported `unsupported` for participants that do not declare the barrier.
12. **Test controls outside the protocol (REL-12).** Every fault, clock and interleaving is driven through launch configuration, the scripted executor, files in the runner's work directory, process signals or runner-side send scheduling. No protocol operation, method, event type or error is reserved for testing.
